# ADR: Vault mirror — one-way sink, repo canonical, single declared writer host

**Date:** 2026-09-24 · **Status:** accepted · **Context:** The storage decision of 2026-09-07 (`~/.claude/rules/common/a1-framework.md`, section "Ablage") put specs, plans, fixes and analyses into the vault and kept roadmap, NEXT cursor and phase state (`docs/product/`, `.a1/phases/`) in the repo. Obsidian, the owner's cockpit, therefore never showed the status asked about most (F-005). Spec 005 was closed as `done` although its mirror FRs were dropped (F-006). Two machines take part: the Mac and the AI server both export `A1_VAULT_ROOT=~/N3URAL-Vault`, and Obsidian Sync replicates that vault to both and to the phone. Locks were `{pid, createdAt}` files judged stale by "pid not running", which is only true on the host that created them. A lock synced from the Mac was therefore reclaimable on the server (F-023). Spec `010-vault-cockpit-contract` (vault `project/a1-specforge/spec/`) closes these gaps. This ADR records the architecture it fixed in its Clarifications of 2026-09-24 and in the decisions taken while building it.

## Decision

### 1. Repo canonical, vault a one-way verbatim sink
The repo stays the only source of truth for product and phase state. `_shared/lib/vault-mirror.cjs` copies the product set (`ROADMAP.md`, `VISION.md`, `NEXT.md`, `index.json`, `features/**`, `audits/**` from `docs/product/`) and the phases set (`GOAL.md`, `PLAN.md`, `STATUS.md`, `VERIFICATION.md` per phase, plus `.a1/RESEARCH.md`) byte-for-byte into `<vault>/project/<slug>/product/` and `…/phases/`. The sets and the exclude list (`observations.jsonl` among them) live in `vault-contract.cjs` and nowhere else. Each file is written to a temp name and renamed over the target. The direction is one-way, never two-way: nothing reads the mirror back, an edit made in Obsidian is overwritten by the next mirror, and `vault sync --prune` removes only regular files inside the two real set folders. The hub note and conflict copies are never written or deleted; conflict copies are reported. `vault sync` rebuilds the mirror on demand, `vault status` reports drift.

### 2. Single writer host
Exactly one host is the vault writer, declared by `A1_VAULT_WRITER_HOST` in `~/.zshenv` beside `A1_VAULT_ROOT`. The writer gate covers three kinds of write. The first is the mirror, both the transaction hook and `vault sync`. The second is every write to a hub note: `vault link-hub`, single and `--all-specs`, and the hub link that `spec init` adds. The third is the bulk backfill `vault lint --fix-type`. Spec authorship is deliberately host-agnostic: `spec init` creates the spec file and `spec update-status` changes it on any host. Those are single files owned by the skill run at hand, while the hub is the most contended file in the vault. Host roles: the **Mac** is the writer. The **AI server** runs a1 and may author and advance specs, but it does not mirror, link hubs or backfill. The **phone** reads and edits notes through Obsidian Sync and is never an a1 host. On a non-writer host a gated write is skipped with one stderr line `[a1-tools] <what> skipped: this host is not the vault writer (<host> ≠ <writer>)`, where `<what>` is `vault mirror`, `vault link-hub`, `spec init hub link` or `vault lint --fix-type`. The exit code stays unchanged, because an a1 run on the server must not fail because of the mirror. Undeclared means every host may write, which keeps single-machine setups working. `vault status --json` reports `host`, `writer_host` (or `undeclared`) and `may_write`. Why one writer: two hosts writing the same file between sync rounds produce Obsidian Sync conflict copies, not merges, and a pid lock cannot serialise across hosts. Tightening the skip to exit 2 is reconsidered after four weeks without conflict copies.

### 3. Host-aware locks
The reservations lock payload carries the creating host: `{pid, createdAt, hostname}`. A lock from the same host keeps the pid test. A lock whose `hostname` differs from `os.hostname()` counts as live, whatever its pid, until the existing `createdAt` stale window expires, because a foreign pid says nothing on this host. A legacy payload without `hostname` keeps today's same-host behaviour. A synced lock that claims the reader's own hostname is treated as same-host by design; that residual spoofing path is accepted and documented, not defended.

### 4. Mirror hook inside the product transaction
Every product-mutating command passes the mirror as the `afterCommit` step of the all-or-nothing product write. It runs after the rename phase and before the lock is released, so it sees committed bytes only. The hook never throws: a failure becomes `vault_mirror: {status: "skipped", reason}` plus one stderr line. It never rolls back the repo write and never changes the exit code. The repo write is the fact; the mirror is a copy that `vault sync` can always redo.

### 5. Vault-free behaviour is byte-identical
Without `A1_VAULT_ROOT` the hook does nothing, prints nothing and returns nothing, so the `vault_mirror` key is omitted from the JSON result. Stdout stays byte-identical to the pre-feature release (SC-002). This wins over the earlier idea of an explicit `inactive` value (team-lead decision 2026-09-26). The repo-local learnings tier is not resolved there either, because resolving it creates `.a1/learnings/` as a side effect.

### 6. Versioned read contract
`a1-tools schema export --json` is the only interface for vault consumers such as obsidian-lumen. It emits the type, status, size, milestone and project vocabularies plus `contract_version` and its alias `schema_version`, both from the one constant `VAULT_CONTRACT_VERSION` in `status-constants.cjs`. Output is a pure function of the source, independent of environment. Any change to an exported vocabulary bumps the version in the same commit. Consumers read the export and never parse a1's modules.

### 7. One frontmatter owner
The CLI stamps `type:` when it creates a file; `spec init` writes `type: spec` as the first key and refuses template drift. The measured vocabulary `spec|wave-plan|bug-report|postmortem|project-analysis|quick-run` stays. `vault lint` validates `type:` and `status:` and reports folded scalars and conflict copies; it rewrites no status. `vault lint --fix-type` is the one sanctioned backfill for legacy files: it stamps every file whose frontmatter parses, is not folded and lacks a type, whatever else lint reports for it, by inserting the `type:` line (or filling an empty one), and preserves every other byte; unparseable and folded files are listed for manual repair, and a second run changes nothing.

### 8. Test isolation from the real vault
Every suite that runs a vault-writing command starts with `unset A1_VAULT_ROOT`. The rule is enforced, not requested (see Consequences).

**Findings closed.** The product and phases mirror closes F-006 and F-005, since the cockpit now shows roadmap and phase state. F-007 is answered by the one-way direction: the repo holds the one status, the vault holds its copy. The hub backfill and `spec init` linking close F-008. One frontmatter owner and `vault lint` close F-021 and F-022. The writer host and host-aware locks close F-023 (all from `analyses/2026-09-24-architecture.md`). Spec `005-vault-first-artifacts` is **superseded** by spec 010. It stays `done`, receives `superseded_by: 010-vault-cockpit-contract`, and spec 010 owns its taken-over FRs.

## Consequences
+ Obsidian shows roadmap, NEXT and phase state without a second status source. A vault edit cannot silently change a1's state.
+ The server can run a1 without risking conflict copies of mirror files or hub notes, and a lock synced from the other machine is no longer reclaimed early.
+ obsidian-lumen reads a versioned contract instead of a1's internals, so a vocabulary change is a visible version bump.
− The mirror trails the repo on non-writer hosts until the Mac runs a product command or `vault sync`. Server-side state reaches the cockpit only through git.
− Specs stay writable on both hosts. Two hosts advancing the same spec between sync rounds can still produce a conflict copy; `vault lint` reports it, and nothing prevents it.
− The writer value must equal `os.hostname()` exactly. On the Mac that name currently comes from DHCP (`MacBookPro.fritz.box`) and changes with the network. Before `A1_VAULT_WRITER_HOST` is set, `sudo scutil --set HostName <stable-name>` must pin it. Otherwise a network change closes the gate, and the Mac quietly becomes a non-writer: exit 0, only the skip line on stderr.
− A crashed foreign lock blocks for the full stale window instead of being reclaimed immediately.
− Test isolation became a rule after an incident. On 2026-09-26, once the Wave-4 hook was live in the worktree, a verification run that inherited the real `A1_VAULT_ROOT` wrote 14 fixture project folders and a `niimo/product/` into `~/N3URAL-Vault`. They were quarantined, reversibly, and the entry count was re-verified at 80 before and after. The fix is `unset A1_VAULT_ROOT` in the affected suites. The sentinel-vault arm `_test-fixtures/a1-vault-cockpit/parts/04c-suite-isolation.sh` enforces it: every suite found by its glob runs against an empty `mktemp -d` vault, and any file in it afterwards turns CI red. A new suite named `run-tests.sh` or `run.sh` is covered automatically.
