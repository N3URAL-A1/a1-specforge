# Wave Plan — EU Sovereignty Section

> Spec: `003-eu-sovereignty-section` · Project: `a1-office-landing` · Size: S · 2 FRs / 4 SCs
> Stack: Next.js 16 App Router, React 19, Tailwind 4, pnpm. Pure frontend marketing-copy + presentation change — no DB, no API routes, no auth, no new dependencies. Single wave, both FRs covered together since they share one content source (`lib/site/content.ts`) and are trivially small individually.

## Planning notes (read before executing)

- **Design decision is locked — "Trust Bento" (Variante A), approved by Robert.** Do not re-litigate layout choice. New standalone section `EuSovereigntySection.tsx`, placed directly after `ValueSection` and before `PricingSection` in `app/[locale]/(site)/start/page.tsx`'s render tree — Nav · Hero · Value · **EU Sovereignty (new)** · Pricing · Contact · Footer, each separated by the existing `section-divider`.
- **Reuse `ValueSection`'s bento pattern 1:1 — do not invent a new card/grid pattern.** Copy the existing structure verbatim: `card-glass` cards inside `StaggerReveal`, `md:grid-cols-3` grid, card 0 gets `md:col-span-2` (large card), cards 1–2 are the two medium cards. Reuse the exact `ACCENT` color-token map (`cyan`/`indigo`/`fuchsia`) and icon-container styling (`h-12 w-12`, `rounded-[10px]`, bordered tint background) already in `ValueSection.tsx:16-34,58-61`. Icons for this section: `MapPin` (card 1, cyan), `KeyRound` (card 2, indigo), `ShieldCheck` (card 3, fuchsia) — Lucide, `strokeWidth={1.5}`, matching `ValueSection`'s icon convention exactly.
- **New standalone component, not a 4th `ValueSection` item.** The spec (edge case, spec line 116) flags that `ValueSection`'s grid CSS assumes exactly 3 items. The approved design avoids that risk entirely by using a *separate* section component that copies the pattern rather than extending `ValueSection` to 4 items — do not attempt the 4-item route, it was not the design that was approved.
- **Status-chip is a new, small visual element, not present in `ValueSection`.** Card 1 (the large "Serverstandort Paris" card) additionally renders a status chip: `"Migration läuft — Kern-Komponenten bereits live"` (DE) / `"Migration in progress — core components already live"` (EN), styled as a small pill (`cyan/10` background tint, rounded-full, small text) with a `pulse-dot` (reuse the exact `pulse-dot` span + `bg-brand-cyan` pattern already used in `Hero.tsx:31`, do not invent a new pulse animation).
- **Existing "Datenschutz ist nie ein Aufpreis" / "Privacy is never an upsell" `ValueSection` item stays untouched (spec edge case, line 115).** The approved design is additive — a new section, not a rewrite of `ValueSection`'s existing 3 items. Do not edit `value.items[1]` in `content.ts`. The new section's copy is more specific (names Scaleway/fr-par/dates) so the two items read as complementary, not contradictory — no dedup logic needed, this is resolved by the additive placement itself.
- **Copy is locked verbatim from the approved concept — do not paraphrase.** Use exactly the EN/DE headline, subline, 4 trust-points, and status-chip text specified below (Task 2). The four trust-points do not map 1:1 to the 3 visual cards — cards 1–3 surface trust-points 1–3 (location, keys, ISO 27001) as their card copy; trust-point 4 ("Built for GDPR from the ground up…") and the fuller Frankfurt/database-migration detail from trust-point 3 are folded into the section subline/large-card body copy so nothing from the approved copy is dropped, while the 3-card visual stays clean (see Task 2 field mapping).
- **Factual accuracy is a hard constraint, not a style preference (spec Discovery — Acceptance Criteria).** Every rendered string in both locales must state: EU provider Scaleway, region fr-par (Paris), key management live since 2026-08-18 and non-extractable by design, database migration described as "in progress"/"underway" (never "complete"), ISO 27001 nameable, SecNumCloud/C5 never claimed. This is directly verifiable by reading the final `content.ts` diff — do this as a self-check before marking the wave done (maps to SC-003).
- **Hero trust mention (FR-002) is copy-only, no layout restructure.** `Hero.tsx`'s eyebrow already renders a `pulse-dot` + text span (`Hero.tsx:30-33`). Add a second, compact line directly below the eyebrow (above or integrated with the `<h1>`) — a short one-line trust mention, NOT a repeat of the full EU-Sovereignty section copy. Must not push the existing dual-CTA row below the fold on common desktop viewports (edge case, spec line 117) and must not touch `HeroParallax`/`.animate-mockup-float`/the dashboard mockup composition. Static text — do not gate it behind any reveal/motion condition (SC-002's reduced-motion acceptance scenario requires it visible unconditionally).
- **No new npm dependencies, no new routes, no logo changes (spec Out of Scope).** `N3URAL //A1` / `A1 //office` brand marks are not touched by this wave.
- **DB / RLS / ENV / Restart: none.** Pure client-rendered marketing copy and presentation; `pnpm build` is the only automated gate. Manual QA is the declared acceptance method for the visual/motion Success Criteria (SC-004), consistent with specs 001/002 — no new test framework is introduced (Out of Scope, spec line 126).
