## Rules for every wave (read once, apply in each wave)

1. **TDD-enforced, autonomous loop.** Write the failing fixture case first, then the code, iterate until green. Only Wave 12's last step is interactive (owner file).
2. **Fixture suite.** The a1-xprov suite is a harness plus one part file per wave (`_test-fixtures/a1-xprov/parts/NN-<group>.sh`, sourced by glob). Each wave adds its own new part (numbers below); it edits an older part only where its own behavior change flips an existing expectation, and names that in the commit.
3. **Fixture origin.** Copy fixtures from real files (real run records, real gitleaks output, real hook payloads, real PLAN.md/spec files), never derive them from the parser under test (`_test-fixtures/CONVENTIONS.md`). Every new CLI subcommand ships hostile cases: path traversal, injection-shaped input (`; rm -rf /`, `$(...)`, backticks), oversized value (≥ 10 000 chars); the case asserts the outcome (exit + stderr, or inert handling). Every new guard ships a RED-proof case whose header names the one production change that turns it red.
4. **Isolation.** Suites run with `unset A1_VAULT_ROOT`, suite `HOME`/`TMPDIR`, review home via `A1_XPROV_CODEX_HOME`; the real `~/.a1-xprov/` and `~/.codex` must stay byte-identical (sha256 + mtime). Kill only own PIDs (`$!`). GNU/Linux portability: no `sed -i ''`, no BSD `date`; guard every temp variable.
4b. **Ad-hoc scripts (added 2026-10-14 after two stray lines in the real `consent-audit.jsonl`).** Since Wave 1, owner stores resolve via `os.userInfo().homedir`; a redirected `HOME` no longer protects anything. Never `require` or run `_shared/lib/xprov-*.cjs` from the live worktree or an unswapped copy outside the suite. Ad-hoc probes only in a tree copy with `xprov-owner-home.cjs` replaced by `_test-fixtures/a1-xprov/fake/xprov-owner-home.cjs`, or through the suite. Reviewers get the same rule in their brief.
5. **Module size.** New logic goes into new modules under `_shared/lib/` (< 400 lines each). Existing files already above 400 lines (`xprov-gate.cjs` 772, `xprov-run.cjs` 888, `xprov-snapshot.cjs` 920, `xprov-preflight.cjs` 778, `xprov.cjs` 413) grow by at most ~25 lines per wave: a `require` plus a call into the new module.
6. **Exit gates per wave** (all must pass before the checkpoint):
   ```bash
   node --check <every touched or new .cjs file>
   bash _test-fixtures/a1-xprov/run-tests.sh          # or the wave's named suite
   for r in _test-fixtures/*/run*.sh; do bash "$r" || break; done
   ```
7. **Deployment chain (all waves):** DB migrations none · RLS/grants none · ENV vars none (no new env var may redirect production paths; test seams go through the tree copy) · services to restart none. Owner-visible effect after merge: `claude plugin update a1-specforge` (Wave 4 ships the plugin hook).
8. **Request-scoped state:** CLI and hook processes are short-lived; no module-global mutable state. Owner-store paths, repo identity and clocks are passed as function parameters (makes fixtures possible without env overrides).

## Plan decisions (made here, flagged for the executor)

- **D-1 Ask order.** The gate evaluates placement before the permit branch. The skill step calls `xprov gate` first; only when it returns `not_applicable` with `external_review_not_permitted` and `xprov permit-check` reports neither permit nor denial does the agent put the consent question and then call the gate again. So scope-exempt work never triggers a consent question, and the question still comes immediately before a gate call.
- **D-2 Owner-home test seam.** After the OS-user-home rule, writers refuse when `$HOME` differs from the passwd home — and the suite runs under a suite `HOME`. The resolver therefore lives in one module (`xprov-owner-home.cjs`); the harness's `make_tree` swaps that module in the tree copy for a fixture resolver (same pattern as the fake runner swap; no env override). One part runs the unswapped module to prove the tripwire.
- **D-3 Retry delays in tests.** Delays (30 s / 120 s) are constants in `xprov-recover.cjs`; `make_tree` rewrites them in the tree copy with `node` (not `sed -i`), so the suite never sleeps.
- **D-4 Scope globs file.** JSON cannot import; `xprov-scope-globs.json` holds the additional globs plus an `include` key naming `quick.cjs#FORBIDDEN_SURFACE_GLOBS`, which `xprov-scope.cjs` resolves via `require('./quick.cjs')`. A fixture asserts that a change in `quick.cjs` changes the classification (no copied list).
- **D-5 Hook fail-closed.** `hooks/hooks.json` calls a shell wrapper `node … || exit 2`, so a crashing or missing node blocks (exit 2) instead of passing (exit 1 is non-blocking in Claude Code). A guarded call that cannot be classified counts as guarded.
